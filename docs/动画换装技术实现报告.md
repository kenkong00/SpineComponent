# 动画换装（🎭 动画换装）技术实现报告

> 适用项目：`spine人物换装识别系统`
> 对应页签：`#tab-actskin`（🎭 动画换装）
> 核心代码：`public/js/actskin.js`、`server.js`（`/api/actskins`）、`vendor/spine-player.js`（Spine 3.8 运行时）

---

## 1. 它要解决什么问题

先分清本系统里两个「换装」页签的本质区别：

| 页签 | 素材来源 | 部件图片 | 角色状态 | 换装难点 |
|------|----------|----------|----------|----------|
| 🎨 切换演示 | `[skin]xxx.json`（PS 皮肤模式导出，**源 JSON**） | 每个部件是**独立 PNG 散图** | 静态摆位、不带动画 | 图片天然可分，难点在「拆皮肤为逐槽位」 |
| 🎭 动画换装 | `[skin]xxx/xxx_explort/`（Spine **导出**目录） | 所有部件**烘焙进一张 atlas png** | 绑骨骼、**会动的动画角色** | 图片合成一张图 + 角色会动，还要逐部件换 |

动画换装的特殊性有两点：

1. **图片被打包成一张图**：没有「手.png / 头.png」这种单文件，无法直接 `<img src>`。
2. **角色会动**：换装不能打断骨骼动画，必须做到「头用 02 皮肤、身体用 01 皮肤」仍照常播放动画。

本报告讲清：① 数据从哪来；② 运行时怎么加载会动角色；③ **逐部位换装的核心技巧**；④ 缩略图怎么从一整张图里裁出来；⑤ 页面结构与交互。

## 2. 整体结构

```
                浏览器（前端）
  ┌──────────────────────────────────────────────────────────┐
  │  #tab-actskin  →  public/js/actskin.js（唯一驱动模块）      │
  │     │                                                      │
  │     ├─ 拉模型列表  ── HTTP ──▶  server.js /api/actskins     │
  │     │                       （扫描 spine/*/*_explort/ 目录）│
  │     │                                                      │
  │     ├─ 读骨架 JSON  ── HTTP ──▶  m.jsonUrl   （拿皮肤名/槽位名）
  │     │                                                      │
  │     ├─ 建播放器     ── SpinePlayer(jsonUrl, atlasUrl, ...)  │
  │     │            （vendor/spine-player.js · Spine 3.8 运行时）│
  │     │                 │                                    │
  │     │                 └─ 渲染：canvas（会动角色）+ 相机视口  │
  │     │                                                      │
  │     ├─ 建混搭皮肤   ── 运行时 API：skeleton.setSkin(mix)    │
  │     │                                                      │
  │     └─ 裁缩略图     ── attachment.region → 离屏 canvas 裁切 │
  └──────────────────────────────────────────────────────────┘
```

**一句话流程**：`服务端扫到带皮肤的动画导出 → 前端用 Spine 运行时把 json+atlas 加载成会动角色 → 把每个槽位的皮肤选择拼成一张自定义 mix 皮肤套上去 → 从 atlas 里裁出每个小图显示在列表里`。

## 3. 服务端：模型从哪来

`server.js` 的 `scanActSkins()` 扫描 `spine/<角色>/<导出目录>/`，满足两个条件的才收录：

- 目录下同时存在 `json + atlas + png`
- **皮肤数 > 1 套** 且 **有动画**

扫描结果 `/api/actskins` 返回的每条模型包含：

```jsonc
{
  "id": "[skin]j0000_explort",
  "label": "[skin]j0000_explort",
  "jsonUrl":  "/spine/[skin]j0000/[skin]j0000_explort/[skin]j0000.json",
  "atlasUrl": "/spine/[skin]j0000/[skin]j0000_explort/[skin]j0000.atlas",
  "spineVersion": "3.8.75",
  "skinCount": 3,        // 皮肤 01/02/03
  "slotCount": 18,       // 18 个可换部位（槽位）
  "animations": ["idle"] // 1 个动画
}
```

前端只拿 URL 和计数，真正的皮肤名 / 槽位名是从 `jsonUrl` 的骨架 JSON 里读的（`S.json.skins[].name`、`S.json.slots[].name`）。

## 4. 运行时加载会动角色

`buildPlayer(m)` 用官方 `spine.SpinePlayer` 创建播放器，关键配置：

```js
const cfg = {
  jsonUrl:  m.jsonUrl,
  atlasUrl: m.atlasUrl,
  animation: S.anim,      // 默认播第一个动画
  showControls: false,    // 不显示官方控制条
  alpha: true,            // 透明背景（配合透明格）
  premultipliedAlpha: false,
  success: (p) => {       // 加载完成回调
    S.player = p;
    S.skeleton = p.skeleton;   // ★ 拿到骨架对象，后面换装全靠它
    applyMix();                 // 套上初始混搭皮肤
    buildThumbs();              // 裁出所有部件小图
    renderAll();                // 刷新左/右视图
  }
};
```

三处「去官方 UI、保干净」的处理（上一轮已修）：

- `loadingScreen.draw = function(){}`：官方加载时会画一个大大的 Spine logo，它只是运行时展示图，**跟素材无关**，直接不画。
- `.spine-player-controls { display:none!important }`：隐藏底部官方按钮条（播放/缩放等），改用页面自己的工具条。
- 背景走 `#akPlayerHost` 的 CSS 透明格（`repeating-conic-gradient`）。

## 5. 核心：逐部位换装是怎么实现的（重点）

### 5.1 Spine 原生能力的限制

Spine 运行时只提供「整套切」：

```js
skeleton.setSkin( skeleton.data.findSkin("02") );  // 整身换成皮肤 02
```

它**没有**「只把头换成 02、其余保留 01」这种 API。这就是动画换装要解决的根本问题。

### 5.2 本方案：自建「混搭皮肤」

思路是——**用一个空 Skin 当容器，从每一套皮肤里挑出对应槽位的 attachment，逐个塞进去，再整体套到骨架上**。

```js
function buildMix() {
  const data = S.skeleton.data;
  const mix = new spine.Skin('mix_' + Date.now());   // 空容器皮肤
  for (const slot of S.slots) {
    const sn = S.choice[slot];        // 这个槽位当前选了哪套皮肤
    if (!sn) continue;                // sn = '' 表示「该部位留空」
    const srcSkin = data.findSkin(sn);
    const idx = S.skeleton.findSlotIndex(slot);
    const att = srcSkin.getAttachment(idx, slot);   // 从那套皮肤取这个部位的附件
    if (att) mix.setAttachment(idx, slot, att);      // 塞进混搭皮肤
  }
  return mix;
}

function applyMix() {
  if (!S.skeleton) return;
  S.skeleton.setSkin(buildMix());          // ★ 一次性套上自定义混搭皮肤
  S.skeleton.setSlotsToSetupPose();        // 回到初始姿势，避免残留动画帧影响
  // 隐藏：把隐藏槽位的附件摘掉
  S.slots.forEach((slot) => {
    if (S.hidden[slot]) { const sl = S.skeleton.findSlot(slot); if (sl) sl.attachment = null; }
  });
}
```

**`S.choice` 就是换装的「灵魂状态」**：`{ 槽位名: 皮肤名 }`，例如 `{ arm_left_Down:"02", body:"01", hair:"03" }`。点一下左栏就改这一项，再调 `applyMix()`。

### 5.3 为什么动画不会被打乱（关键原理）

动画（如 `idle`）的**时间线只动骨骼（bones），不动 attachment**。经核对骨架 JSON 的动画定义，里面只有 `bones` 类时间线，没有改 attachment 的轨道。

→ 结论：一旦把混搭皮肤 `setSkin` 套好，动画照常驱动骨骼运动，**每个槽位挂的附件保持不变**，于是「头用 02、身用 01」这种任意混搭在动画播放期间稳稳成立。

### 5.4 缩放：不改运行时的相机黑盒

缩放不碰 Spine 内部，只操作播放器每帧渲染用的相机视口 `currentViewport`：

```js
// 缩放 = 把视口围绕中心收缩为 1/k（k = 放大倍率）
function applyZoom() {
  const b = S.baseViewport, k = S.zoom;
  const w = b.width / k, h = b.height / k;
  p.currentViewport.x = b.x + (b.width - w) / 2;
  p.currentViewport.y = b.y + (b.height - h) / 2;
  p.currentViewport.width = w;
  p.currentViewport.height = h;
}
```

`baseViewport` 在每次切换动作后清空重取，保证「换动作后仍以该动作的自适应画面为基准」。

## 6. 缩略图：从一整张 atlas 图里裁部件

「切换演示」的部件是独立 PNG，直接能显示；动画换装图片全在 `xxx.png` 一张图里。解决办法：**Spine 运行时在加载 atlas 时，已经为每个 attachment 算好了它在图集里的精确矩形坐标**（`attachment.region`）。

`buildThumbs()` 在播放器加载后遍历所有皮肤的所有附件：

```js
function buildThumbs() {
  S.thumbs = {};
  const data = S.skeleton.data;
  data.skins.forEach((sk) => {
    sk.getAttachments().forEach((e) => {            // e: {slotIndex, name, attachment}
      const att = e.attachment;
      const reg = att && att.region;                // 图集里的精确矩形
      if (!reg || !reg.texture) return;
      const img = reg.texture.getImage();           // 整张 atlas png（运行时已加载）
      const url = cropRegion(img, reg);             // 裁成小图
      (S.thumbs[sk.name] = S.thumbs[sk.name] || {})[data.slots[e.slotIndex].name] = url;
    });
  });
}
```

### 6.1 旋转区域的还原（最易踩坑处）

图集打包时会把部件**旋转 90° 竖着塞**以省空间，标记 `rotate: true`。这类区域在图集里的存储矩形是**宽高互换**的。还原方向从运行时源码 `RegionAttachment.setRegion` 的角点映射反推得出：

> `rotate: true` 时，页内矩形为 `(x, y, 高, 宽)`，需**顺时针转 90°** 才是原方向。
> （运行时依据：`region.v = y / pageH` 从顶部计、无 flipY；`setRegion` 把 rotating 的四个角点映射到 attachment 局部坐标，可推出为 CW 90°。）

```js
function cropRegion(img, reg) {
  const w = Math.round(reg.width), h = Math.round(reg.height);
  const c = document.createElement('canvas');
  c.width = w; c.height = h;
  const ctx = c.getContext('2d');
  if (reg.degrees === 90) {                 // 旋转区域：顺时针转 90° 还原
    ctx.translate(w, 0);
    ctx.rotate(Math.PI / 2);
    ctx.drawImage(img, reg.x, reg.y, h, w, 0, 0, h, w);
  } else {
    ctx.drawImage(img, reg.x, reg.y, w, h, 0, 0, w, h);
  }
  return c.toDataURL('image/png');
}
```

裁出的 dataURL 存进 `S.thumbs[皮肤][槽位]`，三个视图复用显示：

| 视图 | 用法 | 元素 |
|------|------|------|
| 游戏式（左栏行） | 当前皮肤的小图 | `#akGame .sk-g .th > img` |
| 矩阵（左栏全览） | 每个「皮肤×部位」格的小图 | `#akMatrix .sk-cell > img` |
| 右侧详情 | 01/02/03 选项卡的小图 + 尺寸 | `#akDetail .sk-opt .im > img` |

实测：3 套皮肤 × 18 部位 = **54 张图全部裁出**；旋转部件 `arm_left_Down` 还原为竖直 `36×76`，方向与舞台人物一致。

## 7. 页面结构与交互

`#tab-actskin` 分三栏：

```
┌─────────────── 左栏（部件列表 / 视图切换） ───────────────┐   右栏（详情）
│  [🎮 游戏式 | ⊞ 矩阵]                                      │  ┌─────────┐
│                                                              │  │ 部位名   │
│  游戏式：每行一个部位                                         │  │ 01 02 03│ ← 缩略图选项卡
│  👁 部位名 [当前小图] ◀ 下拉 ▶                                │  │ ∅ 留空   │
│                                                              │  │ 显示开关 │
│  矩阵：部位 \ 皮肤 的网格，每格一张小图                        │  │ 信息     │
│                                                              │  │ 骨骼/区域│
├─────────────── 中栏（舞台） ────────────────────────────────┤  └─────────┘
│  #akPlayerHost：Spine canvas（会动的角色，透明格背景）        │
│  工具条：⏸播放 ▶整套轮播 🔁循环 🐢速度 🔍缩放 🎲随机 ♻重置 📷截图
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

交互动作 → 状态变化：
- 点左栏行 / 下拉 / ◀▶ → 改 `S.choice[slot]` → `applyMix()`（实时换装）
- 点 👁 → 改 `S.hidden[slot]` → 摘掉/挂回该附件
- 右侧选项卡点 01/02/03 → 同样改 `S.choice` 并即时刷新
- 整套切换按钮 / 随机 → 批量改 `S.choice`
- **保存换装**：把 `S.choice` 这张「部位→皮肤」表发给 `/api/skinmix` 存下，以后在换装库随时读回重新套到这个会动角色（存的是表、不含图片，所以只要素材还在就能一直用）

## 9. 已知限制与可扩展点

- **`S.choice` 依赖运行时**：列表小图在播放器加载完成后才生成（success 回调里 `buildThumbs()`），所以页签首次显示需等角色载入。
- **旋转还原硬编码 CW 90°**：基于本图集 `rotate: true` 的语义；若将来素材用 `rotate: 180/270`（Spine 4.x 支持），需扩展 `cropRegion` 的分支。
- **缩略图是整图裁切**：保留图集里的去白边（trim）信息，因此小图比原始部件略小，是正常表现。
- **可扩展**：加「换装对比」并排预览、导出混搭后的新 atlas、或把动画换装结果反向写回导出版 JSON（参考切换演示的 `/api/skin/merge`）。

---

## 10. 通俗小结

> 动画换装 = **Spine 会动角色 + 自建混搭皮肤 + atlas 现场裁图**。
> 1. 角色用官方运行时加载，图片都在一张图里、骨骼会动；
> 2. 换装不搞 Spine 不支持的「单部件切」，而是**自己 new 一个 Skin，把每个部位想要的那套皮肤的 attachment 拼进去**，一次 `setSkin` 套上；
> 3. 因为动画只动骨头不动附件，拼好的混搭在动画播放时稳稳保持；
> 4. 列表里每张小图，是从那张 atlas 大图按运行时记录的坐标**实时裁出来**的（旋转部件顺时针转正）。
> 就这样，做到了和「切换演示」一模一样的逐部位自由换装，且角色依旧在动。
