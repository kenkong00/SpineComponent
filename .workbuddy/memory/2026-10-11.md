## 新增「🎨 切换演示」页签（皮肤 × 部位 自由混搭）—— 完成并实测通过

**背景**：用户给了 `spine/[skin]j0000/`，是 PSD 用 Spine「皮肤」模式导出的源 JSON
（`skins` 里并列 01/02/03 三套皮肤，每套给每个 slot 一份 attachment，图片在 `[skin]images/01|02|03/`）。
Spine 里只能整套 `setSkin`，用户要的是「某一套皮肤里的某一个部件单独换」。

**做了什么**
- 服务端 `server.js`
  - `isSkinSourceJson()`：不是导出版 + skins 是对象 + (皮肤数>1 或没有 default) → 皮肤型模型。
  - `buildDeepImageIndex()`：把角色目录下**所有**图片按「末尾 1~3 段路径」建索引，
    所以附件名 `"02/head"` 能命中 `[skin]images/02/head.png`（不必知道 images 目录叫什么）。
  - `resolveSkinImage()`：精确路径 → `皮肤名/文件名` → 同名文件（同皮肤目录优先）。
  - `scanSkinModels()` / `parseSkinModel()`：输出「部位 × 皮肤」选项矩阵；
    **bbox 取所有皮肤所有部位的并集**，切换皮肤时画面不跳。
  - 新接口：`GET /api/skinmodels`、`GET /api/skinmodel?id=`、
    `POST /api/skin/merge`（逐部位选择合并成一个**新 skin** 写进 JSON，无 default 时同时写成 default）、
    `GET|POST /api/skinmix`、`GET|DELETE /api/skinmix/:id`（预设存 `data/skins/`）。
- 前端 `public/js/skin.js`（新文件，window.Skin）+ index.html 新页签 + style.css 新样式。
  - 左：模型下拉 + 整套切换按钮 + 「部位 × 皮肤」矩阵（点格子 = 换这一个部位，点部位名 = 选中，👁 = 隐藏）。
  - 中：舞台（缩放/背景/导出 PNG），工具栏有 `▶ 整套轮播`（700ms）、`🎲 随机混搭`、`↺ 重置`。
  - 右：选中部位的详情（各皮肤大图点选、`∅ 留空`、骨骼/附件名/占位框/中心坐标/源图尺寸）。
  - 底部：导出合并皮肤 JSON / 保存混搭 / 混搭库。

**实测证据**（Edge 无头 + CDP，1600×950）
- `/api/skinmodels` → 1 个模型，3 套皮肤 / 18 部位 / 54 个附件选项，**54 个附件图全部命中**（noImg 为空）。
- 舞台 18 个部件全部渲染；逐部位改 head=02 / hair=03 / body=02 → choice 正确、画面颜色按皮肤变。
- 整套切换 02 → `uniq(["02"])`；留空 head → parts 里 head 消失、显示 17；隐藏 → 16；全部显示 → 恢复。
- 轮播按钮状态与循环正常；保存/读取混搭库正常；六个页签全走一遍 **0 个 JS 报错**、无被裁剪容器。

**素材结论**：三套皮肤确实是三套配色（head 均色 01=182,161,150 / 02=145,145,128 / 03=131,97,107），
但用户给的这批 PNG 本身是**半透明**的（head 不透明像素仅 74%、hair 46%），所以看着发灰，不是渲染问题。

**归档**：`验证截图/19-切换演示-整套皮肤01.png`、`20-…逐部位混搭5处.png`、`21-…混搭库.png`。

## 修复：选中部件出现白底（CSS 类名冲突，`public/css/style.css`）

**现象**：装配台 / 切换演示里选中任一部件，会套上一块白底（圆角、图片四周内缩）。
用户报「明明选中的部件是 PNG 透明底」。

**根因（实测定位）**
- CDP 读 `#skCanvas .part.sel` 计算样式：`background=rgb(255,255,255)`、`padding=5px 8px`、
  `border=1px solid`、`border-radius=8px` —— 而 `.part` 在 CSS 里根本没有背景声明。
- 用「遍历 `document.styleSheets` + `sel.matches(rule.selectorText)`」扫描命中规则，抓到真凶是
  `style.css:64` 的 `.sel,.inp{...background:#fff;border-radius:8px;padding:5px 8px...}`：
  它本是 **`<select class="sel">` 的表单样式**，但「选中态」也用了 `.sel` 这个类名
  （`.part.sel` / `.lyr.sel` / `.sk-row.sel`），于是被一起串上了。
- 佐证手法：给元素内联 `background:rgba(255,0,0,.65)` → 舞台白块变红，确认白块属于该 div；
  清空内联后 computed 又变回白，证明来源是 CSS 层叠。

**修复（治本，非 quick fix）**
1. 表单选择器限定元素类型：`.sel,.inp` → `select.sel,.inp`，`.sel:focus` → `select.sel:focus`，`.sel.sm` → `select.sel.sm`。
2. 防御加固：`.part{...;background:transparent;border:0;padding:0}`。
   顺带修掉「选中时被 padding 8px/5px 内缩、部件渲染尺寸偏小」的隐藏问题。

**实测验证**
- `#canvas .part.sel`、`#skCanvas .part.sel` → `bg=rgba(0,0,0,0) / padding=0 / border=0`，只剩蓝色虚线 outline。
- `.lyr` 行高选中与未选中均 46px（此前会被撑高）。
- 全站 **9 个 `<select class="sel">`** computed 全部保持 `bg=#fff / 1px solid / radius 8px / padding 5px 8px 或 4px 6px`，无回归。
- 归档对比图：`验证截图/22-修复-选中部件白底已去除.png`（左修复前 / 右修复后）。

## 切换演示新增「游戏式」视图（下拉 + 左右箭头）—— 完成并实测通过

**需求**：矩阵是「部位 × 皮肤」全格展示，皮肤一多（用户设想 30 套）就没法用。
要一种像游戏捏人那样的逐部位切换：◀ ▶ 箭头循环 + 下拉直达。

**实现**（`skin.js` / `index.html` / `style.css`）
- 左栏加视图条：`🎮 游戏式` / `⊞ 矩阵`（`.tgl` 高亮），选择存 `localStorage.skView`，**默认游戏式**。
- 游戏式每行 `.sk-g`：👁 隐藏 + 部位名（点=选中进详情）+ 当前缩略图（34px 棋盘格底）+ ◀ + `<select>`（含 `∅ 留空`）+ ▶。
- `partSeq(slot) = availSkins(slot).concat([''])` —— 留空排最后，箭头 `(i+dir+len)%len` 循环回绕。
- `renderView()` 按当前视图分发；原来所有 `renderMatrix()` 调用点（loadModel/renderAll/舞台点选/轮播）都改成它，
  两种视图共享同一份 `S.choice`，切换视图不丢状态。
- 行数只与**部位数**线性相关、与皮肤数无关 → 30/50 套皮肤也不膨胀（只是 select 的 option 变多）。

**实测**（Edge 无头 + CDP）：18 行全渲染；▶ 单击 01→02；下拉选 03 生效且详情/状态栏同步；
循环序列 `01→02→03→∅→01`，从第一套 ◀ 回绕到 ∅；👁 隐藏→行置灰、显示 17；切到矩阵后选择状态保留（矩阵里同样显示 02）；
0 JS 报错。归档 `验证截图/23、24、25`。

## 新增「🎭 动画换装」页签（会动的角色，逐部位混搭皮肤）—— 完成并实测通过

**需求**：`spine/[skin]j0000/[skin]j0000_explort/` 是 Spine「导出」目录（json+atlas+一张整合 png），
角色已绑骨骼、会动、有 3 套皮肤。Spine 运行时只能 `setSkin(整套)`，用户要「单部件任意换」且不影响动画。

**技术核心（已验证可行）**：用 `skeleton.setSkin(自建 mix 皮肤)` 做逐部位混搭。
- SpinePlayer success 回调拿到 `p.skeleton`；`buildMix()` 对每个槽位从 `skeleton.data.findSkin(sn)` 取对应附件，
  塞进 `new spine.Skin(name)`；`skeleton.setSkin(mix); skeleton.setSlotsToSetupPose()`。
- **关键前提已确认**：该角色 `animation` 只有 `bones` 时间线、**没有 attachment 时间线**，所以 mix 皮肤设好后稳定保持、动画照常播。
- 切换 ≈ 30 套时同样只用 `setAttachment` 按槽位取，运行时零压力（动画只动骨骼）。

**素材事实**：导出 JSON 的 `skins` 是**数组**（皮肤名 `01/02/03`，18 槽位，附件名==槽位名只换 atlas 区域），
动画只有一条 `animation`。`[skin]j0000_explort` 经 `scanActSkins()` 命中（skinCount>1 且有动画）。

**实现**：`server.js` 新增 `GET /api/actskins`（`findExports` 补 `skinCount`）；前端新 `public/js/actskin.js`
（window.ActSkin）+ index.html 新页签（复用 spine-player）+ app.js 接线。UI 与「切换演示」同构：
游戏式/矩阵两视图、◀▶循环、整套切换、∅留空、🎲随机、↺重置、保存/换装库（复用 `skinmix` 接口，modelId 区分）。
图片已打包进 atlas，无单张缩略图 → 详情面板明确说明「右边会动的角色就是实时预览」。

**实测**（Edge 无头 + CDP）：初始 18 槽位区域全 `01`；`trackTime` 8.74→10.24→11.44 实时推进（动画在播）；
改 `arm_right_up` → 该槽位区域变 `02/arm_right_up`、其余仍 `01`，动画继续；
整套 02 → `uniq[02]`；全部留空 → 显示 0；随机 → 皮肤构成 `[02,01,03]`；
保存「冒烟测试」→ `/api/skinmix` 落盘 18 部位、三皮肤混搭；0 JS 报错。归档 `验证截图/26~29`。

## 修复「动画换装」三大问题（用户截图反馈：小人物 + 大 spine logo + 底部按钮）

**根因（全部实测确认，不是素材问题）**：
1. **canvas 0×0**：spine-player.js 不自带任何 CSS（无 spine-player.css，也不自动注入），
   canvas 尺寸只能来自 width 属性 → 播放器在隐藏页签里创建时 `clientWidth=0`，
   `resize(Expand)` 每帧把 canvas.width 写成 0，死循环。实测 attr `[0,0]`、rect `[0,0]`。
   动画台没这毛病是因为它有 `.player-host>div,.player-host canvas{width/height:100%!important}` 兜底，actskin 没复用。
2. **大 "spine" 字 + 底部按钮 = 官方播放器控制条裸奔**：`spine-player-controls` 无样式
   （`.spine-player-controls-hidden` 类在但 display:block），里面含 6 个按钮 + spine logo SVG
   被拉满宽 → 用户以为素材里有，其实不在。另有 LoadingScreen 中央大 logo（base64 内嵌，加载后 1s 淡出）。
3. **无缩放**：原实现没有缩放控件。

**修法**（`style.css` + `index.html` + `actskin.js`）：
- style.css 补最小播放器样式：`.spine-player{position:relative;100%}`、
  `.spine-player-canvas{position:absolute;100%/100%}`、`.spine-player-controls{display:none!important}`。
- `#akPlayerHost` 从 `.stage-center` 包裹改为**绝对定位铺满 `.stage-scroll`**
  （inset:10px）—— `.stage` 高度靠内容撑，百分比链会断裂，这是第二个隐藏坑。
- `buildPlayer()` 后立刻 `player.loadingScreen.draw = function(){}` 杀掉 Spine 大 logo。
- 新增缩放：滑条 `akZoom`(0.4~3) + 画面滚轮；原理 = 把运行时 `player.currentViewport`
  围绕中心收缩为 1/k（drawFrame 每帧按它算相机，zoom≈1）。`setAnim`/重载后
  `baseViewport=null` 重新取基准，缩放倍率保持。
- 默认背景改「透明格」（checker）。

**实测**：canvas 864×735 ✓；controls display:none ✓；loading.draw 已替换 ✓；
zoom 2.0 → viewport 209×492→105×246（精确减半）✓；
leg_right_UP ▶ → 槽位区域 `02/leg_right_UP`、trackTime 持续推进 ✓；
动画台回归：切全局角色 j0003 加载 export → canvas 1298×793、控制条也隐藏 ✓。
归档 `验证截图/30、31`。

## 动画换装：atlas 烘焙图裁出部件缩略图（第 6 项需求）
- 需求：动画换装的部件列表/详情没有小图（图片烘焙在一张 atlas png 里），要求做到和切换演示一样的显示效果。
- 做法：`actskin.js` 新增 `buildThumbs()`——播放器 success 后遍历 `skeleton.data.skins` 的 `getAttachments()`，每个 attachment 的 `region`（TextureAtlasRegion）记录图集内精确矩形，用离屏 canvas 裁出 → dataURL 存 `S.thumbs[皮肤][slot]`。
- **rotate:true 还原规则（从 vendor setRegion 角点映射推导）**：页内矩形宽高互换（源矩形 = x,y,h,w），顺时针转 90° 还原：`ctx.translate(w,0); ctx.rotate(PI/2); drawImage(img, x, y, h, w, 0,0,h,w)`。运行时 `region.v = y/pageH` 从顶部计、无 flipY。
- 三个视图全换图：游戏式行 `.th <img>`、矩阵格 `<img>`、详情面板 `.sk-opt .im <img>` + 尺寸 sub（复用既有 sk-* CSS，无新增样式）。
- CDP 实测：thumbs 01=18/02=18/03=18；游戏式 18/18 行有图；矩阵 54/54 格有图；rotate 部件 arm_left_Down 尺寸 36×76 方向正确；截图 32/33/34 归档。
