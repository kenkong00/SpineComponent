# 2026-10-09 · Spine 人物装配工坊（新项目）

## 做了什么
在 `I:\TREA work\window操作界面\spine人物换装识别系统` 从零搭了一套「Spine 拆件还原 + 换装」网页系统。用户需求：把 PhotoshopToSpine 导出的源 JSON + `images/` 散图在网页还原成人物，**每个部件独立可替换**；另外 `export*/` 里的 json+atlas+png 要能在网页播动作。

## 技术结论（踩过的关键坑，务必记住）

### 1. 源 JSON 还原公式（已验证 6 个角色全部像素级还原）
源 JSON（含 `PhotoshopToSpine` 字段、`skins` 是 **对象**）里
`skins.default[slot][attachment] = {x,y,width,height}`，其中 `x,y` 是**部件中心**、**Y 轴向上**（Spine 坐标）。
转画布坐标（Y 向下、原点 = bbox 左上）：
```
left0 = x - w/2 - bbox.x0
top0  = bbox.y1 - (y + h/2)
```
用 Python/PIL 先做过对照实验，j0001、j0003 与导出图完全一致。

### 2. 【大坑】Spine 3.8 官方 web 运行时**硬拒绝** 3.8.75 数据
`spine-runtimes` 仓库 `3.8` 分支（jsDelivr: `cdn.jsdelivr.net/gh/EsotericSoftware/spine-runtimes@3.8/spine-ts/build/spine-player.js`，473KB）
里有两处：
```js
if ("3.8.75" == skeletonData.version)
    throw new Error("Unsupported skeleton data, please export with a newer version of Spine.");
```
而同一个文件**又**是按 3.8.75 的新格式写的（`root.skins` 当**数组**遍历、mesh 用 `hull/edges`）。
**处理**：把这两处 throw 注释掉（改成 `if (false) {}`）后一切正常 —— 已实测 3 个导出版（j0003 8 个动作 / pet0001 6 个 / pet0002 8 个）都能播。
`vendor/spine-player.js` 现在就是打过补丁的版本。**重装运行时必须重新打这个补丁。**

### 3. slot 没写 attachment = Spine 里默认不显示
PSD 导出的侧身/闭眼/换嘴/换眼等「备用件」在 `slots` 里没有 `attachment` 字段，
默认必须隐藏，否则还原出来是错的（j0003 会多出侧身）。这些被识别成「备用/变体」部件，可一键换上。
- j0003：8 个变体（body_side / face_side / hair_side / eye_*_close / hand_left_1 / toe_right_2 / arm_right2）
- pet0001：6 个变体（mouth_2/3、eye_L_1/2、eye_R_1/2）

### 4. 装配台是「PSD 原始摆位」，不是骨骼姿态
源 JSON 是扁平布局（1 根 root 骨）。pet0002 的触手在 PSD 里就是画散开的，靠 rig 的骨骼掰到位，
所以**装配台里 pet0002 看起来是散的 —— 这是对的**（等于"拖进 Spine 的样子"）。骨骼装配后的正确形态看**动画台**。
j0000–j0003、pet0001 的 PSD 本来就是拼好的，装配台直接就对。

### 5. 另外
- 导出版 mesh 附件都**无权重**（`bones` 字段为空），全刚性件。
- `x,y` 之类的部件图尺寸与源 JSON 的 `width/height` 完全一致。
- 角色 JSON 命名不统一：`j0001/J0001_512X512.json`、`j0002/J0002.json` 等 → 扫描时按「与文件夹同名优先」+ 内容判断。
